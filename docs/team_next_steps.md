# 后续工作说明

这份项目已经完成了"框架 + API + UI + JSON 输出 + 流式返回"。后续的核心工作是结合软件测试知识完善内容。下面按位置说明应该在哪里做修改或补充。

## 1. 情景选择与需求文本

位置：docs/example_inputs.md

你可以：
- 新增一个完整场景（系统概述 + 功能需求）
- 或替换 Example 1 的场景文本

要求：
- 需求要清晰、有边界、有约束
- 最好包含价格/数量/状态/时间等规则

## 2. Prompt 调优

位置：app/services/prompt_manager.py

你可以：
- 在 V1/V2/V3/V4 模板中调整指令文字
- 对于 EP/BVA 技术：系统使用两步生成（第一步等价类+边界值分析，第二步基于分析结果生成测试用例）
- 对于 Decision Table 技术：系统使用三步生成（第一步条件/动作识别，第二步规则生成，第三步测试用例生成）
- 强制规则：哪些必须是 valid/invalid
- 强制 BVA 只能围绕规则边界生成
- 明确必须覆盖的负例

同时记录：
- 调整前后输出差异
- 出现的问题与改进方法

## 3. 输出结果校对

位置：页面右侧输出结果

你需要人工检查：
- 等价类是否正确（valid/invalid）
- 边界值是否贴合规则
- 测试用例是否覆盖关键场景
- 是否有遗漏的输入变量

可把结论写进报告的"分析与改进"部分。

## 4. 报告与展示材料

位置：design.md + 你们自己的报告文档

你们需要补齐：
- 情景描述与需求文本
- EP/BVA 结果
- 用例与覆盖分析
- AI 局限与改进过程

## 5. 运行与演示

位置：README.md

只要在 README 里照步骤启动服务，然后在浏览器里输入需求即可演示。

如需新增场景模板或对 Prompt 进行更细的规则约束，请在团队内部沟通后再改动。
